Which connection method?
Connect directly Already an agent A plain API Pick this when You know exactly how the request and reply are shaped, and want that shape kept precisely. A team or vendor tells you their agent is A2A and gives you a server address. All you have is an API — a URL, some endpoints and a key. What you need The base URL, credentials, and the field names your API uses for the message and the reply. The server address, and credentials for the agents you want to use. The base URL, its API documentation, and a key. Who does the work You map the fields once; Cogentiq calls it exactly as you described. Nobody — the agent already exists. Cogentiq just connects to it. Cogentiq builds the agent around your API and hosts it.

Not sure? Choose a plain API. It works for anything with a URL, and you can always register it properly later if the team publishes a real agent. Reach for Connect it directly only when the auto-built adapter gets a field wrong and you need to fix the mapping by hand.
