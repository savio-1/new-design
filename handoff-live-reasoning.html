Live reasoning trace and follow-up responses

Everything needed to build the assistant turn that shows one live task line, opens into a reasoning trace of thoughts and railed task blocks, and ends in a three-question series the reader reviews and submits as a single message. Values below are measured from the working prototype, not estimated.

1 · Flow

One conversation, two assistant turns. The flow is linear and stops after the second answer. Nothing loops.

WorkingComposer shows the stop square. The live task line shimmers blue and renames itself to the task running now. The trace under it is collapsed by default; "Hide steps / Show steps" opens it.
Thought throughThe line stops shimmering, loses its icon, drops to 14px and reads "See reasoning ›". The trace tucks away. The answer streams in below with the single assistant mark.
Questions openA card asks three questions one at a time. The composer locks and reads "Answer the questions above to carry on". Skip takes the assistant's own pick. Nothing is sent until Submit responses, or Skip on the last question.
SubmittedThe card fades out. One user message posts with each question at 12px over its answer at 16px, tagging any answer that came from Skip. The composer unlocks.
Second turnSame live line and trace pattern, shorter. Step one, "Reading your answers", lists every question with the answer that came back, so the reasoning shows what it was given. Two working steps follow, each after a thought. Then the second answer, composed from the answers given. The composer returns to idle. End.

4 · Layout and spacing

Thread column
780px, centred, padding 24px top, 16px sides, 80px bottom. The bottom padding is what keeps the newest line 80px clear of the composer when scrolled to the end.
Message rail
Every assistant block is a 24px icon column + 12px gap + content. The live line, the trace steps, the answer and the question card all share this rail, so text starts at the same x.
Between messages
16px. A collapsed trace pulls one gap back (margin-top −16px) so the finished line sits exactly 16px above the answer.
Composer
780px, radius 24, padding 12, 1px top rule in Blue/500 when active.

Spacing scale inside the trace

One 4px scale. Distance falls as relatedness rises. Collapsed folds must contribute no gap (pull back their parent's gap with a negative margin).

5 · Reasoning turn

Live task line

Grid: 24px assistant mark, 12px gap, then a flex head with the title cell and a right-aligned toggle. The title is a one-cell grid so an outgoing and incoming label overlap during the swap.

  • Text names the task running right now. Every task narration and every thought calls setTask(label); a step headline sets it too. Same text twice is a no-op.
  • Style Body1 500 in Text/Coloured-blue with a shimmer sweep and an animated ellipsis. Shimmer: 100° gradient blue → #D9EFFF → blue, 200% width, 1.8s linear loop, clipped to text.
  • Toggle "Hide steps" / "Show steps" with a 12px chevron, Caption1 secondary, 4/8 padding, radius 8. Rotates 90° when open. aria-expanded mirrors the trace.
  • Default The trace starts collapsed. Only the blue line shows until the reader opens it. Content keeps building underneath while collapsed.

Finished line

  • The assistant mark is hidden (keep the 24px column so text stays on the rail).
  • Title becomes a button: "See reasoning" + 12px right chevron, Body2 secondary, padding 2/6, radius 6, hover fill Card/bg-1. Chevron rotates 90° when open. The right-hand toggle is removed.
  • The trace folds; all groups and rows inside reset to closed.
  • The answer follows at 16px with the only assistant mark in the turn.

Trace container

Collapsible via grid-template-rows: 1fr → 0fr with opacity, 550ms on the same easing. Inner column gap 16px. Trace-level thoughts carry 36px left padding so they land on the rail of the step titles.

6 · Inside the trace

Step

Headline row: 24px icon box (16px glyph, secondary) + 12px + Body1 500 white title + 8px + 16px chevron. Below it, content indented 36px. While working the title shimmers grey; done shows the up chevron; the whole step is click-to-fold once done.

Thought

A paragraph of first-person reasoning that sets up the next block or reacts to the last one. Body2 secondary, 588px measure. Streams at 26ms per word. Sits outside any rail. A thought between two runs of tasks closes one rail and opens the next.

Task block

Consecutive task lines are wrapped in one container with a 1px left rail in Strokes/Card/Default, 12px left padding, 6px row gap. A task line is a 16px icon + 6px + Body2 secondary text. While running: spinning logo glyph, streamed text, shimmer, animated ellipsis. Settled: the real icon replaces the spinner. Skill chips (2/6 padding, radius 8, Card/bg-1) hang 2px under their task inside the rail.

Group

Heading: 16px icon + 8px + Body2 500 white label + 12px chevron (right when closed, down when open). Its fold is a grid collapse (350ms). When open, the fold carries a 1px left rail in Strokes/Card/Default aligned under the icon's centre: margin-left 7px, padding-left 16px, so content lands 24px in. The note line ("Found 3 definitions that match") is Caption1 secondary. Rows are 4px apart with a 24px right inset.

Evidence row

Radius 8, fill Page/bg-3, 1px stroke, padding 8/12. Top line: 14px or 16px icon + Caption1 500 name + 12px chevron; optional right-aligned source tag or badge. Definition rows expand on click to show the definition and Synonyms / Parent terms chips. Data-binding rows show the qualified table name in mono and a Column · Type · Value table under a hairline.

Divider

1px rule in Strokes/Card/Default with no margin of its own; the 16px step gap frames it on both sides.

7 · Follow-up questions

Rendered after the first answer, on the message rail with an empty 24px column. Blocks the composer until submitted.

Data model

type Option   = { label: string; task?: string; reply: string }
type Question = {
  q: string                 // shown Body1 500 white
  placeholder: string       // custom field hint
  options: Option[4]
  best: number              // index Skip selects
  recommend?: boolean       // show the Recommended chip on options[best]
  custom: (text) => string  // reply fragment for a typed answer
}
type Answer = Option & { custom: boolean; viaSkip?: boolean }
// reply = answers.filter(Boolean).map(a => a.reply).join(' ')

Three questions ship: which risk to take further (best 2, recommended), who is reading it (best 0, no badge, only the reader knows), how much policy wording to carry (best 0, recommended).

Card anatomy

  • Card 688px, radius 12, fill Page/bg-3, 1px stroke, padding 16, column gap 12.
  • Top row "Question n of 3" Caption1 secondary, space-between, an 84px progress strip of three 3px segments (gap 5, radius 2). Unvisited: Strokes/Card/Default. Answered: Text/Coloured-blue. Current: Blue/500 scaled 1.7× tall. Segments are buttons that jump to any question already reached.
  • Question Body1 500 white. Streams in the first time it is shown; renders instantly on revisit.
  • Options 4 rows, gap 8. Row: padding 10/12, radius 8, fill Page/bg-2, 1px stroke, gap 10. Key badge 20×20 radius 6 Card/bg-1 with a mono digit. Label Body2 secondary, fills. Optional Recommended chip: padding 1/7, radius 6, Badge/blue fill, Caption2 in Text/Coloured-blue, right-aligned.
  • Chosen stroke Blue/500, fill Blue/500 at 12%, label white, key badge Blue/500 with white digit. Hover on others: fill Card/bg-1, stroke Strokes/Card/Hover, −1px lift.
  • Custom answer full-width field: radius 10, fill Type/bg-1, 1px stroke, padding 6 / 6 / 6 / 12, focus stroke Blue/500. Placeholder Body2 tertiary. 28px round send button, lights Blue/500 when there is text.
  • Footer 12px top padding over a 1px rule. Left: two 32px round chevron buttons (1px stroke, no fill). Right: Skip (tonal-2, 32px, radius 80, padding 0/14) and, on the last question only, Submit responses (Blue/500, white label, send glyph).

Behaviour

  • Picking an option records it and auto-advances after 420ms. On the last question it stays and lights Submit.
  • Enter or the send glyph in the custom field records a typed answer the same way.
  • Back is enabled from question 2. Next is enabled when the current question is answered or has already been passed. Segments jump within the reached range.
  • Returning to an answered question shows the pick highlighted (or the typed text in the field). Changing it re-advances.
  • Skip selects options[best] in front of the reader, marks it viaSkip, then advances. On the last question it submits.
  • Submit is enabled whenever it is visible. It locks the card, fades it out (300ms, −8px), removes it, and resolves the answers.
  • Keyboard 1–4 pick an option (not while typing), ← → move between reached questions, Enter in the field records a typed answer.
  • Height Hold the stage's min-height at the outgoing step's height until the incoming step is fully built, then ease to the new height over 300ms. Without this the card collapses 258px in one frame when a longer question streams in.

Composer lock

While the card is open: fill Page/bg-3, top rule Strokes/Card/Default instead of Blue/500, caret hidden, a 14px lock glyph followed by "Answer the questions above to carry on" in tertiary, and all controls at 40% opacity with pointer events off. Unlocks on submit. A replay always starts unlocked.

8 · Submitted message

One user bubble (Disabled/Tonal-1 fill, radius 12, padding 14/16, column gap 10, max 530px, right-aligned). For each answered question, a pair: the question in Caption1 at 58% white, then the answer in Body1 regular white. Pairs after the first carry a 10px top padding and a 1px rule at 14% white. An answer that came from Skip gets a Caption2 tag under it at 14% white fill and 72% white text: "Skipped, took your recommendation" where the badge was shown, otherwise "Skipped, took your pick".

Answers as the first reasoning step

The second turn opens its trace with a step titled "Reading your answers" (16px answers icon: a speech bubble with a tick). Under the title, one railed task line narrates "Going through the {n} answers you sent", then settles. Below it sits a list of answer rows, one per answered question, in question order, each rising in 260ms after the last.

List
Column, 4px gap, 24px right padding so it lines up with the thoughts.
Row
Column, 2px gap, padding 8/12, radius 8, fill Card/bg-5 #1B1B1B, 1px stroke #323232.
Top line
Question in Caption1 12/16, −0.24px, #BDBDBD; tag pushed right with a 12px gap.
Answer
Medium 14/20, −0.56px, #BDBDBD. It stays secondary: inside the reasoning only headlines are white.
Tag
Caption2 10/14, padding 1/7, radius 6, fill Blue 14% (rgba(13,153,255,.14)), text #80CAFF. "Skipped · my recommendation" when the question had a recommended pick, "Skipped · my pick" when it did not, "In your words" for a typed answer. No tag for a picked option.
After
The step marks done (up chevron), folds after 500ms like every finished step, and the turn's first thought follows. That thought depends on the skips: all skipped, some skipped ("You answered {a} and left {s} to me…"), or none.

11 · Accessibility

  • The steps toggle and the See reasoning button carry aria-expanded and an aria-label naming the action.
  • Expandable evidence rows are role="button", tabindex="0", toggle on Enter and Space, and expose aria-expanded.
  • Progress segments and chevron buttons have labels ("Question 2", "Previous question", "Next question"). The custom field is labelled "Your own answer"; its send glyph "Use this answer".
  • Focus ring: 2px Blue/500 outline, 2px offset, radius 6.
  • The locked composer sets aria-disabled="true" and states why in text, not colour alone.
  • Text contrast: secondary #BDBDBD on #212121 is 8.2:1; blue #80CAFF on #212121 is 8.7:1.
  • Reduced motion: the streaming keeps its fade, the shimmer becomes static secondary text, spinners stop.

12 · Acceptance checks

Each of these was measured on the prototype in Chromium. Match them.

  • Trace is collapsed on first paint; the toggle reads "Show steps".
  • Blue line text changes with every task and thought; the text left edge equals the step title left edge (both 36px into the message rail).
  • Finished line reads "See reasoning ›" at 14px with no icon; distance to the answer is exactly 16px.
  • Exactly one assistant mark per answer; none on finished lines.
  • Inside the reasoning only step headlines and group headings compute to #FFFFFF; all other text is #BDBDBD.
  • Task rail is 1px #424242; task lines are 6px apart; a thought never sits inside a rail.
  • Opened group rail lands on the icon centre line (±1px) and content starts 24px in.
  • Steps 16px apart, headline to content 8px, content items 12px, rule centred with 16px each side.
  • Newest line holds 80px above the composer at 1280×900, 1280×1000 and 390×780.
  • Card height does not change by more than the eased transition when moving from question 2 to 3 (was a 258px single-frame drop before the min-height hold).
  • Composer is locked from the moment the card renders until submit, and unlocked before the second turn.
  • Skipping all three questions still submits three answers, each tagged.
  • Back into a skipped question shows the recommended option selected.
  • No horizontal scroll at 390px.
  • Turn two's first step is "Reading your answers", with one row per answered question in question order; picked answers have no tag, skipped ones read "Skipped · my pick" or "Skipped · my recommendation", typed ones read "In your words".
  • Inside the answers step the question is 12px and the answer 14px medium, both #BDBDBD.
  • Replay resets to one user message, no answers, one live line.
