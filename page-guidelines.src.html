The frame

Every module page is the same frame: a rail, a sidebar, a header, a filters bar and a scrolling content ground. A person moving between Models, Agents and Guardrails should feel the chrome hold still and only the content change — so the surfaces and strokes below are not a starting point to adapt, they are fixed.

Cards per row

The content area is 1076px at the standard 1440 window. Rather than fixing a column count, set a minimum card width and let the grid work it out — a module then keeps its intended density on a wide screen and drops a column on a narrow one instead of squeezing.

Two per row
--cq-card-min: 430px → cards of 532px. Use when the card carries a sentence of description that needs room to read. This is the Model hub.
Three per row
--cq-card-min: 340px → cards of 350px. Use when the card is a short label and a couple of tags — tools, integrations, templates.
Never
a hard repeat(3, 1fr). It survives 1440 and breaks everywhere else.

Card anatomy

The card's shell is fixed so a grid of them reads as a grid. What sits inside the middle is the module's — a model shows a description, a tool might show a version and an owner, a template might show nothing at all.

hover it — the tag row is the one part that must behave the same everywhere
fixed
Surface --backgrounds-page-bg-2, padding 16px, radius 12px, --shadow-card.
fixed
Selected state: 1px --strokes-type-focus. Hover: --strokes-line-1. Never a fill change — a filled hover fights the selected row.
fixed
Top row: a 32px logo tile then the title. Bottom row: tags left, identity and actions right.
fixed
Tags are grey at rest and take their tone on hover or selection. Put .cq-tint on the card so a row and a card behave the same for the same content.
free
Everything between those two rows — a description, a metric, a progress bar, nothing.
free
Height. 120px is the default; use .cq-card--auto when the content genuinely varies. Keep it constant within one grid.
free
Which pills appear, and how many. One neutral id pill plus up to three tones reads well; past that the row wraps and the card stops scanning.

Views & the detail panel

A module that lists things gets the same two views and the same way of opening one. Reuse them rather than inventing a third — the toggle, the selected state and the panel are muscle memory across the product.

Grid ↔ table
Offer both when rows have more than three comparable fields. The toggle sits at the right of the filter row, .cq-seg--icon. Both views read the same filtered set, so switching mid-filter loses nothing.
Opening one
Click a card or a row to open the 420px panel. Click the same one again, press Escape, or click outside to close. Selection lives on the item, not the panel, so both views show it.
Panel contents
Tags, title, description, actions, then .cq-kv rows under a .cq-section-label. Sections are the module's; the row shape is not.
Creating one
The primary action opens a modal, not a new page. Two steps where configuration is involved: what it is, then how it runs. The test pane only appears once there is something to test.
Empty states
Filters that match nothing say so in the content area and leave the chrome alone. Never blank the filters bar — the way back is the count and the controls.

Building a new module

The order that avoids rework. Steps 1–3 are mechanical; the judgement is in 4 and 5.

Copy the shell. .cq-page and its regions, unchanged. Do not restyle the chrome to suit the module.
Name the page. Header carries the module name and one line saying what it is for. The filters-bar title reflects the active sidebar filter — “All models” becomes “Claude models”.
Fill the sidebar. Whatever the module filters by. Keep “All …” first and make it the default.
Choose the density. Does the card need a sentence? Two per row. Is it a label and tags? Three. Decide before designing the card, not after.
Design the card middle. Keep the top and bottom rows; change only what sits between them. Check it at the smallest width the grid allows.
Wire the panel. Reuse .cq-kv rows. If a value needs more than a row, it belongs in a tab, not a taller row.
Check both themes and the narrow window. If a colour only works in one, it is a literal that should have been a token.
