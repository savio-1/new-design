Cogentiq Design System

One stylesheet, linked by every screen in the platform. Token names match the Figma variable names one for one, so a value changed in Figma maps to exactly one line of CSS. Dark is the product default; set data-mode="light" on the root element to switch, and every component follows because none of them hold a colour of their own.

This page embeds that stylesheet verbatim — every specimen below is the real component, not a redrawing of it. Click any token or icon to copy it.

01

Tokens

92 tokens in eleven groups. Each swatch shows both themes: the top-left triangle is dark, the bottom-right light. Where a token holds one value it is theme-invariant by design — the ramps and the radii, mostly.

Never hard-code a colour in a screen. If a value is missing, add a token here rather than a literal there. The stylesheet ships only the ramp steps its own components use, so a screen that needs another step declares it in that page's :root — an undefined custom property fails silently and takes the whole gradient with it.

Ink is a token too: .cq-text-primary, .cq-text-secondary, .cq-text-tertiary. A value, a label and a legend all stay in those three; a coloured mark beside them carries identity, never the text itself.
03

Buttons

One base class plus a variant. Height is 36px, or 24px with --sm for a row-level action inside a table.

.cq-btn.cq-btn--primary The one action a screen wants. At most one per view.
.cq-btn--tonal Secondary actions, and every action in a table row.
.cq-btn--ghost · .cq-icon-btn Dismissals, and icon-only controls in a header.
.cq-btn--wide Fills its container — modal footers, empty states.
04

Form fields

A field is a label row over a control. The control carries the focus ring; the label row carries the optional count or hint.

.cq-field > .cq-control Single-line input, 40px.
.cq-control--textarea Same control, allowed to grow.
.cq-search Leading glyph, no label — it sits in a toolbar.
.cq-checkbox Native input, restyled — keyboard behaviour intact.
05

Filters & popovers

The dropdown is a button; the popover it opens is a sibling positioned by the group around them. Open one below to see the real thing.

.cq-filter-group > .cq-dropdown + .cq-pop > .cq-pop__list > .cq-option Filters live in one row above the content they filter, never beside it.
06

Tags, badges & pills

Three shapes for three jobs: a tag names a thing, a badge states a condition, a status reports live state. Tones come in pairs — a badge background with its matching stroke and text — so a tone is one attribute, not three declarations.

08

Navigation

The platform rail is the one piece of furniture every screen shares. It overlays rather than pushes, so the content gutter stays constant whether it is collapsed or open — which is why no page has to reflow when it opens.

09

Surfaces, radius & shadow

Four surfaces stack in a fixed order — page, card, nested, popover — and each is a token rather than an opacity. Border, fill, radius and shadow each say "separate object", so they are spent by role and not stamped on every block.

--radius-sm · md · lg · xl · full Tags, then buttons and inputs, then cards and modals, then floating bars.
--shadow-tab · --shadow-modal · --shadow-pop A shadow tuned for a white ground all but vanishes on a dark one, so these are picked per theme, not softened.

10

Icons

A per-document sprite of <symbol> definitions, drawn in currentColor so an icon inherits the ink of whatever it sits in. A <use> pointing at a symbol that is not in this document renders nothing at all, with no console error — so the sprite travels with the page.
